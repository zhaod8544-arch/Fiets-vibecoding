## 二、项目概述

### 2.1 项目背景

企业内部使用飞书进行日常沟通，员工希望沿用已有身份进入工作记录与绩效汇报系统。首版由用户本人试用，先验证持续记录工作、关联个人目标和借助 AI 整理季度成果的实际价值，再扩展团队审批与环评流程。

1. **身份重复维护**：重新建立账号和密码会增加试用负担。系统需要识别真实飞书身份，同一员工再次登录后能够继续查看此前记录，避免仅凭同名造成账号关联错误。
2. **目标与工作记录分离**：季度目标与每周工作往往分别记录，季度末难以逐项确认哪些工作推动了关键结果，哪些目标缺少实际成果支撑。系统需要建立事项与 KR 的关联。
3. **季度汇报整理成本高**：员工需要从多周记录中查找成果、合并重复事项并说明差距。AI 汇总应减少重复整理，同时允许员工核对来源和编辑正文。
4. **建议分缺少解释**：仅给出一个分数无法帮助员工了解目标推进情况。系统需区分匹配度、完成度、AI 建议分和本人自评分，对证据不足的内容明确标注。
5. **历史汇报依据变化**：目标和周报可能继续编辑，已确认汇报需要保留当时采用的材料和评分依据，确保后续查看仍能还原原始评估背景。

### 2.2 项目建设目标

1. **真实身份进入系统**：用户通过真实飞书授权进入系统，首次登录关联个人账号，再次登录可查看原有目标、周报和归档。授权取消、失效或企业身份不符合要求时明确反馈，不产生虚假登录状态，完成从身份识别到个人数据访问的验证。
2. **建立可追踪的季度记录**：用户可维护季度 O、KR、衡量指标与实际进度，记录周报并关联工作事项。报告保存不要求逐次审批或确认，保存成功后可重新查询；目标和报告的变化保留必要版本，使 AI 汇报具备连续且可核查的材料。
3. **提供有依据的 AI 汇报**：用户可随时生成季度阶段性预览，查看成果总结、KR 匹配分析、完成情况、差距和建议分。重要结论附具体来源，重复成果合并处理，未来计划不计为已完成成果，材料不足时明确说明，避免把生成成功等同于评估准确。
4. **完成个人自评归档闭环**：用户编辑汇报正文，填写自评分及理由后确认归档，退出并重新登录仍可查看。归档保存材料快照，后续编辑目标或周报不改变已归档结果；修订形成新版本。个人自评与未来主管确认的正式绩效结果明确区分。

### 2.3 项目建设范围

**系统端**：PC 端 Web 应用；本版不建设独立移动端。

**功能模块**：飞书登录、我的季度目标、我的周报、我的绩效汇报。AI 分析分别纳入周报关联推荐和绩效汇报生成，不另设独立业务菜单。

**数据范围**：指定企业内真实飞书用户的身份关联，以及登录用户本人的季度目标、KR、周报事项、分析记录、自评草稿和归档快照。其他用户可登录时，也只能访问本人业务数据。

**后续范围**：日报、月报、全组织同步、上下级关系、飞书提醒、LD 审批、360 环评和正式绩效评定不进入首版。后续保留员工拟定目标、LD 确认，先审批环评名单再发起评价、LD 审批结果并可编辑评分和意见、审批期间可更换环评人、员工查看匿名反馈、最终由 LD 综合评定的业务约定。

### 3.5 功能详细设计

### 3.5.1 飞书登录

#### （一）功能需求概述

员工通过真实飞书身份登录系统，独立维护本人季度目标、周报和绩效汇报。首版允许同一企业的不同账号分别使用，每个账号仅可访问本人业务数据。

#### （二）功能设计

**真实授权登录**

登录页提供“通过飞书登录”。员工点击后进入飞书授权，授权完成后系统核实真实身份及企业归属，成功建立或复用关联账号后进入个人业务页面。授权处理中不允许重复发起同一次登录；授权未完成或核实失败时保持未登录状态，显示对应原因并提供重试入口。

**账号关联与身份数据**

首次成功登录自动建立关联账号，再次登录复用原账号。身份数据由飞书提供或系统自动记录，用户无需填写登录表单，也不能编辑身份关联字段。

| 字段名称 | 类型 | 长度限制 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|---|
| 企业标识 | 文本 | 完整保存，不截断 | 是 | 无 | 来源于飞书真实身份，必须与允许登录的企业一致 |
| 稳定用户标识 | 文本 | 完整保存，不截断 | 是 | 无 | 来源于飞书真实身份，与企业标识共同确定唯一账号 |
| 关联账号 | 账号标识 | 完整保存，不截断 | 是 | 首次成功登录时自动建立 | 系统记录，作为本人业务数据的所属人依据 |
| 姓名 | 文本 | 使用飞书返回的完整姓名 | 否 | 飞书当前姓名 | 每次成功登录同步；姓名缺失不影响已核实身份的关联，不参与账号匹配 |
| 登录时间 | 日期时间 | 不适用 | 是 | 当前成功登录时间 | 系统记录最近一次成功登录时间 |
| 登录状态 | 单选状态 | 不适用 | 是 | 未登录 | 未登录、登录处理中、已登录；身份核实及账号关联均成功后才成为已登录 |
| 会话有效期限 | 日期时间 | 不适用 | 是 | 按现有系统会话配置确定 | 登录成功后自动记录，超过期限后必须重新授权 |

**登录成功后的访问**

首次成功登录进入“我的季度目标”，再次登录进入当前季度“我的周报”。当前季度按 Asia/Shanghai 日历时间确定。业务导航仅显示“我的季度目标”“我的周报”“我的绩效汇报”。

**会话失效处理**

会话失效后停止个人业务访问，返回登录页，提示“登录已失效，请通过飞书重新登录。”。员工重新完成真实飞书授权后，继续访问同一关联账号下已保存的数据。

**退出登录**

已登录员工可点击“退出登录”，直接结束当前系统会话，返回登录页并提示“已退出登录。”。退出成功后，原会话不能继续访问业务。退出不删除关联账号或已保存的本人数据，不改变飞书本身的登录状态及其他浏览器的有效系统会话。退出失败保留当前状态，提示“退出失败，请重试。”。

**业务规则**

- 企业标识与稳定用户标识的组合唯一；再次登录复用原账号。姓名相同但稳定用户标识不同的员工分别关联独立账号；账号建立成功后进入个人页面，无额外建号确认。
- 企业归属不符时拒绝登录，不建立关联账号，提示“当前飞书账号不属于允许登录的企业，请更换账号。”。
- 首次登录尚无本人目标时，提示“本季度暂无目标，请新增季度目标”，不能将其他员工记录作为初始数据。
- 查询、新增、编辑、分析、归档和历史访问均以当前登录身份确定所属人。访问他人记录时拒绝操作，提示“无权访问该记录。”，不展示其内容。
- 授权状态不匹配、授权凭据失效或重复无效授权返回时拒绝登录，使用对应异常提示，不重复建立关联账号。
- 身份核实或账号关联保存失败时不进入已登录状态，提示“登录未完成，请重试。”。
- 飞书应用密钥及登录凭证不向用户展示，不作为 AI 分析材料发送；此类信息不得出现在汇报正文或分析结果中。

**边界与异常**

| 场景 | 处理方式 | 提示文案 |
|---|---|---|
| 员工取消授权 | 返回登录页，提供重新登录 | “已取消飞书授权，请重新登录。” |
| 飞书登录配置缺失 | 停止登录，允许重新尝试 | “飞书登录尚未配置，请联系应用管理员。” |
| 账号无应用使用权限 | 拒绝登录，提供重新登录 | “当前飞书账号无权使用此应用，请联系企业管理员。” |
| 企业归属不符 | 拒绝登录，允许更换账号 | “当前飞书账号不属于允许登录的企业，请更换账号。” |
| 企业标识或稳定用户标识缺失 | 不建立账号 | “未能获取有效飞书身份，请重新授权。” |
| 授权状态不匹配 | 拒绝本次登录 | “本次授权请求无效，请重新登录。” |
| 授权凭据失效或重复无效返回 | 拒绝本次登录 | “本次授权已失效，请重新登录。” |
| 授权失败、网络失败或超时 | 保持未登录，提供重试 | “飞书登录失败，请重试。” |
| 账号关联保存失败 | 不进入已登录状态 | “登录未完成，请重试。” |
| 会话失效 | 停止访问并返回登录页 | “登录已失效，请通过飞书重新登录。” |
| 越权访问 | 拒绝操作、不展示记录；无权限操作入口隐藏 | “无权访问该记录。” |

#### （三）业务逻辑关联

- **数据来源依赖**：企业标识、稳定用户标识及姓名来源于飞书真实身份，需先完成企业应用、允许企业、授权返回地址和身份读取权限配置。

#### （二）功能设计

**查询／筛选功能**

年度与季度共同确定查询范围，默认展示当前季度本人已保存的目标。季度按 Asia/Shanghai 日历时间划分。

| 筛选字段 | 类型 | 说明 |
|---|---|---|

| 季度 | 单选 | 第一季度、第二季度、第三季度、第四季度；默认当前季度 |

未保存内容切换周期时提示“当前内容尚未保存，是否放弃编辑并切换？”，选择“继续编辑”保留内容，选择“放弃并切换”查询新周期。

**列表功能**

按 O 展示所属 KR，完整展示所选季度目标，不分页。

**新增 O 与 KR 功能**

|---|---|---|---|---|---|

| 指标类型 | 单选 | 不适用 | 是 | 未选择 | 越大越好、越小越好、定性 |

| 实际值 | 数值 | 有限数值，最多 4 位小数 | 数值指标必填 | 空 | 本人填写，不自动填入 0 |

- O 下无至少 1 个完整 KR 时阻止保存，提示“每个 O 至少需要 1 个完整 KR”；合法保存生效并提示“季度目标已保存并生效”。
- 同一次保存重复提交只形成一次结果和一个版本；成功提示“季度目标已保存并生效”，失败不形成有效版本。
- 越大越好按实际值大于或等于目标值核查，越小越好按实际值小于或等于目标值核查，展示“已达标”或“未达标”；零或负目标值仍采用相同核查规则，不强制通过除法换算进度。
- 定性指标展示标准与实际情况，提示“请对照完成标准核查实际完成情况”，不自动将描述判定为已完成。
- 编辑实际进度时提示“实际进度由本人维护，AI 不会自动修改”；本人填报进度不替代完成分析、AI 匹配度或绩效分。
- 最新目标或进度保存后，旧材料分析标记“已过时”，提示“目标或进度已编辑，已有分析已过时，可重新生成”；新分析采用最新保存版本。
- 目标被周报或快照引用后编辑仍保留原版本和引用，历史查看提示“历史版本仅供查看”；已有归档保持原内容，提示“后续目标编辑不影响已归档内容”。

| 无目标 | 提供新增入口 | “本季度暂无目标，请新增季度目标” |

### 3.5.3 我的周报

#### （一）功能需求概述

本人按周记录工作事项、成果、阻碍和下周计划，关联事项所属季度的 KR，并通过 AI 推荐辅助选择。周报自动保存并保留版本，为季度汇报提供工作材料，无需逐次确认或审批。

#### （二）功能设计

**查询／筛选功能**

按本人周报的周起始日期查询，默认当前周。周按 Asia/Shanghai 周一至周日划分；选择日期自动归入其所在周，起止周均包含。

| 筛选字段 | 类型 | 说明 |
|---|---|---|
| 起始周 | 日期选择 | 默认当前周，查询该周及之后 |
| 结束周 | 日期选择 | 默认当前周，查询该周及之前 |

条件为“与”关系；单项为空不限制对应边界，全部清空查询本人全部历史。结束周早于起始周时阻止查询，提示“结束周不能早于起始周”。

**列表功能**

| 列名 | 字段类型 | 说明 |
|---|---|---|
| 周起止日期 | 日期范围 | 所属周自动确定周一与周日 |
| 工作事项数量 | 整数 | 当前已保存版本的事项数量 |
| 最近保存时间 | 日期时间 | 系统记录最近成功保存时间 |
| 保存版本 | 正整数 | 系统记录最近成功版本 |
| 操作 | 操作入口 | 编辑、详情查看 |

按周起始日期倒序，默认每页 10 条，可选 10、20、50 条；分页保留条件。空列表显示“暂无周报，请新增周报”。

**新增功能**

点击“新增周报”，选择所属周并录入事项。日期、工作、成果与 KR 按事项填写；阻碍和计划按整份周报填写。

| 字段名称 | 类型 | 长度限制 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|---|
| 所属周 | 周选择 | 有效日历周 | 是 | 当前周 | 首次保存后不能改周 |
| 事项日期 | 日期 | 所属周内有效日期 | 是 | 所选周包含今天时为今天，否则为周一 | 决定事项年度与季度 |
| 工作事项 | 多行文本 | 1～2000 字 | 是 | 空 | 实际开展的工作，纯空白无效 |
| 成果说明 | 多行文本 | 最多 3000 字 | 否 | 空 | 实际成果，进行中可暂不填写 |
| 关联 KR | 多选 | 不设额外数量限制 | 否 | 未关联 | 本人事项日期所属季度已生效 KR |
| 阻碍 | 多行文本 | 最多 2000 字 | 否 | 空 | 本周阻碍 |
| 下周计划 | 多行文本 | 最多 2000 字 | 否 | 空 | 不计为已完成成果 |

系统记录周报与事项标识、所属人、周起止、保存版本与保存时间。标识完整保存，所属人取登录身份；首次保存为版本 1，内容变化并保存成功产生新版本，无变化重试不增加版本。

无效所属周提示“请选择有效的所属周”；工作为空提示“请填写工作事项”；事项日期无效提示“事项日期须在所属周内”；文本超长提示“{字段名称}不能超过{最大长度}字”，替换为实际值。校验失败保留内容，不保存无效版本。

**编辑与自动保存功能**

点击“编辑”自动填入最新保存内容，校验同新增，所属周不变；允许历史周报编辑。有效内容停止编辑 2 秒后自动保存，依次显示“未保存”“保存中”“已保存”或“保存失败”。

保存中继续编辑时继续保存最新内容，最新内容未保存前不能显示“已保存”。失败保留编辑，提示“保存失败，请重试。当前编辑内容已保留”，可点击“重试保存”；首次及后续保存成功均显示“已保存”。

**关联 KR 功能**

事项可关联多个本人同季度 KR，也可未关联；跨季度周各事项分别确定季度。无候选提示“事项所属季度暂无 KR，可先保存未关联事项”，不阻止周报保存。

选择他人或其他季度 KR 时阻止保存，提示“请选择事项所属季度的本人 KR”。日期变化导致关联跨季度时提示“事项日期所属季度已变化，请重新选择关联 KR”，由本人重新选择或改为未关联后保存。

**AI 关联推荐功能**

本人点击“AI 关联推荐”，只采用当前已保存事项及本人对应季度生效 KR，展示推荐 KR、原因和来源事项；推荐不覆盖手动关联，本人通过“关联 KR”采纳或调整后保存生效。

未保存、校验失败或保存失败时阻止推荐，提示“请先保存当前周报，再获取 AI 关联推荐”。同一保存版本的进行中推荐请求合并，提示“该版本正在推荐，请稍候”。推荐成功提示“关联推荐已生成，请核对后选择 KR”。

无候选提示“事项所属季度暂无 KR，可先保存未关联事项”；无合适推荐提示“暂无合适的 KR 推荐，可手动关联”。

**详情查看功能**

点击“详情查看”，展示周起止、完整事项及日期、成果、KR、阻碍、计划、保存时间与版本。可查看历史成功保存版本，仅供查看并提示“历史版本仅供查看”。

**业务规则**

- 每人每周仅一份，发现重复新增时打开已有记录并提示“本周已有周报，已打开已有记录”，同时操作不能重复建报。
- 没有至少 1 条完整日期及工作事项时不保存，提示“每份周报至少需要 1 条完整工作事项”。
- 事项按日期归入季度，跨季度周仍一份；季度分析只采用对应季度事项，展示来源日期，不能以整周起始季度归属所有事项。
- 成果空仍可保存进行中工作，提示“未填写成果说明的事项不作为已完成成果”；未来计划、未来日期和仅关联 KR 不能据此认定完成。
- 手动关联优先，不改变实际值或认定目标完成；查看推荐时提示“关联仅表示相关性，不代表目标已完成”。重复成果保留原记录，AI 汇总合并不重复计分。
- 切换周、筛选或离开存在未保存内容时提示“当前周报尚未保存，是否放弃编辑并离开？”，可“继续编辑”或“放弃并离开”。
- 本版不提供周报、事项或版本删除，也不提供提交审批。

**边界与异常**

| 场景 | 处理方式 | 提示文案 |
|---|---|---|
| 保存失败 | 保留编辑，重试最新内容 | “保存失败，请重试。当前编辑内容已保留” |
| 多窗口冲突 | 不覆盖新版本，保留本次编辑 | “周报已在其他窗口编辑，请保留当前内容并重新加载最新版本” |
| 冲突后重新加载 | 确认采用最新；继续编辑取消重载 | “重新加载将替换当前编辑内容，请先复制保留。是否继续？” |
| AI 未配置 | 保留关联，仍可手动关联 | “AI 服务尚未配置，暂无法推荐，可手动关联 KR” |
| AI 推荐超时 | 保留关联，可重试 | “AI 关联推荐超时，请重试” |
| AI 限流 | 保留关联，可稍后重试 | “AI 关联推荐请求过于频繁，请稍后重试” |
| AI 返回无效结果 | 不应用推荐，可重试 | “AI 关联推荐结果无效，请重试” |
| 推荐期间内容变化 | 不覆盖关联，重新推荐 | “周报内容已变化，请基于最新已保存版本重新推荐” |
| 越权访问 | 隐藏入口，拒绝他人记录与版本访问 | “无权访问该记录。” |
| 登录失效 | 停止保存和推荐，保留编辑内容并返回登录页 | “登录已失效，请通过飞书重新登录。” |

#### （三）业务逻辑关联

- 飞书身份确定本人范围；失效停止周报操作并提示“登录已失效，请通过飞书重新登录。”。

- 输入和归档快照保留当时版本及关联；后续编辑不改变归档，提示“后续周报编辑不影响已归档内容”。

**筛选功能**

年度、季度、状态为“与”关系，点击“查询”展示本人汇报，周期按 Asia/Shanghai 划分。

| 筛选字段 | 类型 | 说明 |
|---|---|---|
| 年度 | 年度选择 | 四位整数，默认当前年度 |
| 季度 | 单选 | 第一季度、第二季度、第三季度、第四季度，默认当前季度 |
| 汇报状态 | 单选 | 全部、草稿、已归档，默认全部 |

无效年度、季度、状态分别提示“请选择有效的四位年度”“请选择有效季度”“请选择有效汇报状态”，阻止查询并保留选择。

**列表功能**

| 列名 | 字段类型 | 说明 |

| 本人自评分 | 数值 | 来源于本人填写，缺失显示“未填写” |
| 材料标记 | 文本 | 系统核查，可同时显示材料不足、阶段性分析、已过时 |
| 最近保存时间／归档时间 | 日期时间 | 系统记录，草稿显示“未归档” |

默认每页 10 条，可选 10、20、50 条，按最近保存或归档时间倒序；切换筛选回第 1 页。空列表显示“暂无符合条件的绩效汇报，可生成预览或新增人工草稿。”。

**生成预览功能**

所选季度点击“生成预览”，采用本人最新保存目标、实际进度及周报事项，保存输入快照并分析。跨季度周仅采用事项日期属于该季度的内容，未保存编辑不参与。

无目标提示“本季度尚无目标，请先补充目标；也可人工填写汇报。”；无已保存事项提示“本季度尚无已保存工作材料，请先补充周报；也可人工填写汇报。”，均不发起 AI 分析。

状态为生成中、生成成功、生成失败；同本人、同周期、同材料版本的进行中请求合并，提示“该材料版本正在生成，请稍候”；不同用户或季度不能合并。

成功提示“预览已生成，请核对分析与来源”。尚未人工编辑的新草稿可填入 AI 正文；已有人工正文、自评分、理由及生成期间人工编辑均保留，新结果独立预览。生成失败不清除旧记录。

**查看分析功能**

点击“查看分析”展示完整结果和材料范围。

| 字段名称 | 字段类型 | 说明 |
|---|---|---|
| O／KR／衡量指标／指标类型 | 文本 | 来源于输入快照中的目标版本 |
| 目标值／完成标准 | 数值／文本 | 本人填报目标，按类型展示 |
| 实际值／实际完成情况／本人填报进度 | 数值／文本／百分比 | 本人已保存内容，缺失如实标记 |
| AI 匹配度／原因 | 数值／文本 | 0～100，最多 2 位小数，证据不足可未评分并说明原因 |
| KR 完成分析 | 文本 | 对照目标、方向及成果说明达成与差距 |
| 相关成果／来源／证据缺口 | 文本 | 去重成果、来源事项及缺少证据 |
| AI 汇报预览 | 文本 | 分析结果，与人工正文分别保存 |
| AI 建议分／评分理由 | 数值／文本 | 0～100，最多 2 位小数；不足时未评分并说明原因 |
| 材料范围／标记 | 日期范围／文本 | 采用的事项日期范围，材料不足、阶段性分析、已过时 |
| 生成时间／材料版本 | 日期时间／版本记录 | 系统记录本次生成及目标、报告版本 |
| 模型标识／评分规则版本 | 文本 | 本次使用的模型及规则，只读 |

本人工作记录标记“本人填报”，AI 结论标记“AI 推断”；来源证明结论引用了哪些材料，不代表对外部成果真实性的独立验证。匹配度不等同于完成度，也不直接换算建议分；建议分不自动填入自评分。

首版评分规则 v1：逐 KR 核对方向、目标、实际情况、成果及来源，先说明达成和差距，再综合对 O 的推动、未达成 KR 与证据支撑提出建议分。理由逐项引用依据并说明保留意见；不设机械权重，不以字数、篇数或措辞给高分。

零或负目标不强制除法换算；定性指标对照标准与成果核查。重复成果合并，未来计划不计完成；本人填报与证据矛盾时明确疑点，不视为证实。

不足以可靠评分时分数留空，提示“材料不足，暂不提供 AI 建议分”，列出缺少的 KR 证据及覆盖范围。0 分仅表示有依据的评分，不代替缺失。季度未结束或材料未覆盖完整季度时提示“当前材料仅支持阶段性分析，不代表完整季度结果”。

**查看来源功能**

点击来源查看本次输入快照；历史查看采用当时归档快照，不能用最新记录替换。

| 来源字段 | 字段类型 | 说明 |
|---|---|---|
| 所属人／年度／季度 | 归属／周期 | 系统记录，仅本人指定季度 |
| 目标及进度版本 | 版本与完整内容 | 当时 O、KR、指标、目标、实际值、标准、单位、截止日期、实际情况与进度 |
| 周报版本及事项 | 版本与完整内容 | 当时周起止、事项日期、工作、成果、阻碍、计划及 KR |
| AI 分析版本 | 分析记录 | 输出、时间、模型及规则；未采用时如实标记 |

快照只读，未采用或缺失材料不虚构补齐。来源无权查看时提示“无权访问该记录。”。

**保存草稿功能**

在所选季度可从空白汇报填写入口“保存草稿”直接开始人工填写；已有草稿点击“编辑”自动填入保存内容，采用手动保存。

| 字段名称 | 类型 | 长度限制 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|---|
| 汇报正文 | 文本 | 最多 20000 字 | 草稿否，归档是 | AI 初始正文或空 | 归档至少 1 字，纯空白无效 |
| 本人自评分 | 数值 | 0～100，最多 2 位小数 | 草稿否，归档是 | 未填写 | 0 为有效自评分 |
| 自评理由 | 文本 | 最多 2000 字 | 草稿否，归档是 | 空 | 归档至少 1 字，纯空白无效 |

草稿只校验已填写项，超长提示“{字段名称}不能超过{最大长度}字”；分数无效提示“本人自评分须为 0～100，最多保留 2 位小数”；归档缺必填提示“请填写{字段名称}”，替换为实际名称及上限。

成功提示“草稿已保存”，失败保留编辑并提示“草稿保存失败，请重试。当前编辑内容已保留”。AI 不可用、未评分或缺目标周报均不阻止合法人工草稿及归档。

**重新生成功能**

点击“重新生成”，先保存并保留人工正文、自评分、理由及旧分析；失败停止生成，提示“当前编辑内容未能保留，请先重试保存”。采用最新保存材料生成新快照，不覆盖人工内容，成功提示“新预览已生成，当前人工编辑内容已保留”。前置条件及重复请求规则同生成预览。

**确认归档功能**

草稿点击“确认归档”，校验正文、自评分及理由；未保存编辑先完整保存，失败或冲突停止归档并保留内容。弹出确认“确认将当前自评汇报归档？归档后该版本仅供查看。”。

确认后完整保存正文、自评分、理由、时间、版本、来源归档版本及目标、进度、周报和采用的 AI 快照；人工路径标记“人工汇报，未采用 AI 分析”，缺失如实记录。所选分析与当前材料版本不一致时，保留分析对应输入快照，并标记已过时，不将不同版本拼作同一次分析。

同次重复确认只形成一个版本，成功提示“自评汇报已归档”；失败不产生半成品，提示“归档失败，请重试。草稿已保留”。季度未结束或 AI 尚生成也可归档合法草稿，后续结果不改变归档。

**历史查看与修订功能**

点击“历史查看”，只读展示归档正文、自评分与理由、AI 建议及 KR 分析、材料范围、版本、时间和来源快照，提示“已归档版本仅供查看，需编辑请新增修订草稿。”。

点击“修订”复制所选归档的正文、自评分、理由及来源关联，记录源版本，提示“已新增修订草稿，原归档版本保留”。新草稿可编辑并归档为新版本，原版本完整保留；材料已变的复制分析标记“已过时”。

**业务规则与边界异常**

- 目标或周报变化使旧分析已过时；生成期间仍保存启动快照，提示“材料已编辑，当前分析已过时，可基于最新材料重新生成”。
- AI 配置缺失、连接失败、超时、限流或格式错误时生成失败，展示类别并提示“AI 分析失败，请重试；也可继续人工填写并归档”，保留旧正文和分析。
- 来源不属于本快照、分数越界或结构无效时不得视为成功，提示“分析结果无效，请重新生成”。
- 未保存离开时提示“当前草稿尚未保存，是否放弃编辑并离开？”，提供“继续编辑”“放弃并离开”；多窗口冲突保留内容不覆盖，提示“草稿已在其他窗口编辑，请保留当前内容并重新加载最新版本”。
- 越权时拒绝内容，隐藏无权限操作，提示“无权访问该记录。”；登录失效停止查询保存并返回登录页，提示“登录已失效，请通过飞书重新登录。”。

#### （三）业务逻辑关联

- 飞书身份决定本人范围，目标与周报提供本季度已保存材料，不混用其他人或季度。
- AI 读取目标进度及工作材料，不改变本人实际值和进度；材料内容不能改变规则或触发外部操作。
- 原始记录与规则变化不改变归档，历史快照可核查；修订形成新草稿与归档版本。

## 四、技术方案

### 4.1 技术架构

复用现有 PC 端管理项目，采用 Vue 3、TypeScript、Vite、Element Plus、Pinia；后端采用 NestJS、Prisma，业务数据存入 MySQL，系统会话及必要运行状态使用 Redis。本版新增个人业务模块，不把已有组织和角色管理页面作为员工业务入口。

开发环境沿用现有前后端独立运行方式；部署可使用现有 Docker Compose 与网关配置。仅部署本版 PC 端、后端、MySQL 与 Redis，不要求构建不存在的移动端项目。新增业务必须具备独立登录校验及记录归属校验，不能沿用未接入认证的占位放行路径。

### 4.2 数据交互

业务请求使用统一成功、失败与数据结果格式，区分登录失效、无权限、校验失败、编辑冲突与外部服务失败。日期时间按 Asia/Shanghai 展示，日历日期与保存时间分别记录。

保存操作携带待编辑内容的版本，冲突时不覆盖他人窗口的最新保存。重复保存、重复归档和同次生成不得产生重复有效结果。AI 任务记录输入快照、生成状态与结果，生成时的材料与归档材料可追溯。

### 4.3 外部系统集成

飞书承担真实授权及登录身份读取；本版不需要全组织通讯录同步，也不发送飞书消息。AI 服务承担文本关联推荐、季度分析及汇报生成；具体供应商、地址、模型与使用额度在接入时确定，避免依赖固定供应商专有能力。

外部服务不可用时显示明确错误。报告记录和人工自评仍可独立使用，不以模拟身份、模拟模型结果替代真实调用。

### 4.4 安全方案

飞书应用密钥和 AI 密钥仅在服务端环境配置，不出现在浏览器资源、业务正文、分析材料或日志。生产访问使用 HTTPS；授权返回校验请求关联状态和身份归属，不将第三方凭证作为系统会话直接暴露。

后端按登录身份限定记录归属，对目标、周报、分析结果、来源快照和归档逐一核查。所有可编辑文字作为不可信内容处理，不能执行脚本，不能使 AI 改变系统权限或执行外部动作。登录、生成、保存及归档记录必要审计信息，禁止记录完整密钥或登录凭证。

## 五、非功能需求

### 5.1 性能需求

首版性能目标按单人试用、最多 5 个同时在线会话、单季度 20 个 O、100 个 KR、1000 条工作事项、单篇周报 100 条事项的基准材料量验证。此规模为测试基准，不作为业务数量上限。

在正常网络、测试材料量及服务可用条件下，非 AI 页面首次可操作时间不超过 3 秒，普通查询与保存请求 95% 在 2 秒内完成；请求发出后 1 秒内显示操作状态。外部飞书授权耗时单独记录，不计为普通保存耗时。

AI 任务发起后 2 秒内可见生成状态；单次生成等待上限为 120 秒，超过上限显示失败并允许重试。生成耗时受模型服务影响，需记录实际耗时；不承诺在外部服务故障时仍满足正常耗时。基准量内不得静默截断材料，大材料可分段处理并保留来源对应关系。

### 5.2 安全需求

无有效系统会话时不能访问业务数据；本人数据隔离不得通过改变人员、周期或记录标识绕过。跨用户访问验证覆盖查询、编辑、生成、归档和来源查看。

凭证只用于授权或服务连接，不参与 AI 工作材料。输出正文不得执行脚本；外部错误经过处理后展示，不泄露内部凭证。限制重复授权与生成请求，避免重复建号和无意重复消耗模型额度。

### 5.3 可用性需求

保存成功的数据在刷新、重新登录和正常服务重启后仍可读取。网络或服务中断时明确区分“未保存”与“已保存”，不展示错误成功提示。

试用环境每天备份业务数据，至少保留最近 7 份每日备份；上线前验证一次备份恢复。每日备份方式下允许恢复点最多落后 24 小时，首版故障恢复目标为 1 个工作日内，实际恢复记录纳入验收。本版不承诺商业级全天候可用率。

AI 失败不阻止人工编辑、自评分和归档，飞书首次授权失败时不提供虚假登录替代。外部服务恢复后可重新尝试。

### 5.4 兼容性需求

正式试用支持验收时 Chrome、Edge 的当前稳定版本，记录具体版本；PC 分辨率以 1366×768 和 1920×1080 验证。键盘输入、中文输入、长文本编辑和页面刷新均需正常使用。

独立手机页面、原生应用、飞书客户端免授权登录和其他浏览器专项适配不属于首版验收承诺。经浏览器完成真实飞书授权即可满足首版登录方式。

| 自评草稿 | 正文、自评分、理由、关联分析、保存版本 | 本人可编辑，生成不能静默覆盖 |
| 归档快照 | 正文、自评分、理由、AI 建议、目标与报告来源、确认时间、归档版本 | 只读，修订关联原归档 |

### 6.2 数据存储要求

试用期内不自动清理身份关联、业务记录、目标版本、周报已保存版本、AI 输入快照或归档。停止试用或正式上线前确定长期保留与删除策略，未确认前不执行批量清理。原始材料编辑不改变历史快照。

首版无附件上传，不规划图片或视频存储。初始业务数据可用空间按至少 1 GB 预留，备份空间另行保留并监测实际增长；达到容量阈值时由环境维护人员处理，不静默丢弃材料。

时间统一以 Asia/Shanghai 日历规则判断季度和周，周一至周日为一周。全局标识保留完整值，不截断匹配；自评分与建议分独立保存，缺失建议分不能保存为 0。

## 七、接口需求

### 7.1 第三方系统接入接口规范

**飞书授权与身份**

飞书登录采用官方用户授权机制，涵盖发起授权、授权码交换用户凭证、读取登录身份。具体接口版本、权限名称、返回字段及凭证生命周期以接入时飞书官方文档为准，不沿用过时示例；实现阶段需记录实际采用的版本与最小权限。

| 环节 | 输入／输出要求 | 失败处理 |
|---|---|---|
| 发起授权 | 指定应用、已登记回调地址、请求关联状态 | 缺配置时停止发起 |
| 授权返回 | 核对状态并处理一次性授权结果 | 取消、失效、重复或状态不匹配时拒绝 |
| 用户身份读取 | 获得可验证企业标识与稳定用户标识，姓名仅展示 | 无身份或不属允许企业时拒绝建号 |
| 系统登录 | 关联账号成功后建立系统会话 | 保存失败不得登录成功 |

App ID、App Secret、允许企业标识、开发及部署回调地址由环境维护人员配置；不能在正文或聊天中要求公开密钥。需由用户本人完成真实授权，企业应用权限与可用范围由具备权限的管理员配置。

**AI 文本分析**

| 项目 | 约束 |
|---|---|
| 输入范围 | 本人、指定季度、生效目标及已保存周报事项；关联推荐只读取当前周报保存版本与候选 KR |
| 输入标记 | 保留用户归属、目标版本、周报版本、事项标识与日期，禁止携带登录凭证 |
| 输出内容 | 推荐关联及原因，或汇报正文、逐 KR 分析、材料说明、建议分与理由、引用来源 |
| 来源约束 | 引用必须存在于本次输入快照，不得引用他人或其他季度材料 |
| 数值约束 | 匹配度与建议分为 0—100，最多 2 位小数；未评分采用缺失值与原因，不以 0 代替 |
| 验证约束 | 结果结构、字段类型、数值范围和引用归属均通过检查才视为成功 |
| 失败分类 | 未配置、连接失败、超时、限流、返回结构无效或来源无效 |
| 调用记录 | 保存任务归属、时间、模型标识、规则版本、输入版本、状态与耗时，不记录密钥 |

AI 服务地址、模型、密钥和使用额度通过运行环境配置。所选服务应支持必要文本容量及结构化结果；不满足时记录接入限制，并在验收前解决，不静默缩减本季度材料。

## 八、项目实施与验收

### 8.1 实施阶段

| 阶段 | 工作范围 | 完成条件 |
|---|---|---|
| 需求与联调准备 | 核对个人版范围、准备飞书应用及 AI 服务 | 需求基线明确，配置项及真实账号可用 |
| 身份与工作记录 | 登录、本人权限、季度目标、周报 | 数据保存后重新登录可查，跨账号访问被拒绝 |
| AI 与个人归档 | 推荐关联、绩效预览、正文编辑、自评、快照与修订 | 分析引用可查，人工路径独立可用，归档只读 |
| 真实试用 | 全流程验证、异常验证、质量核对 | 满足验收清单，问题及实际调用结果已记录 |

不在需求阶段承诺固定开发周数；实际进度根据应用配置、模型接入与开发结果记录。主管审批与环评不作为本版上线前置条件。

### 8.2 系统培训服务

面向本人使用者提供简要操作说明：飞书登录、季度目标填写、周报自动保存、AI 来源核对、自评分与归档、修订及异常重试。面向环境维护人员提供配置项说明、启动部署说明和备份恢复说明，材料不包含真实密钥。

### 8.3 验收标准

**连续场景**

由用户本人使用真实飞书账号完成：登录 → 新增 1 个 O 与 2 个 KR → 保存 2 篇实际周报 → 维护实际进度 → 获取关联推荐 → 生成季度绩效预览 → 核对来源 → 编辑正文、填写自评分与理由 → 确认归档 → 退出并重新登录查看归档。

两篇周报只验证闭环，不能证明季度材料充分。若建议分因材料不足为空，必须说明缺失依据；另使用足够材料的样例核对合法建议分及理由，不能以无依据给分满足验收。

| 验收项 | 必须达到的结果 |
|---|---|
| 真实身份 | 授权来自飞书；账号企业归属正确，再次登录不重复建号 |
| 个人权限 | 两个有效测试身份或相应后端验证覆盖他人目标、周报、分析和快照，越权均被拒绝 |
| 目标记录 | O/KR 保存直接生效，零值、负值、定性口径和版本查询正常，不强制套除法 |
| 周报记录 | 自动保存状态真实，刷新可查，每人每周仅一份；跨季度事项按日期正确归属 |
| AI 关联 | 使用真实模型和已保存版本，不虚构 KR，不覆盖手动关联 |
| AI 汇报 | 使用真实模型，重要结论能查来源，重复成果不重复计入，未来计划不当完成成果 |
| 材料不足 | 显示缺口及阶段性标记，缺失建议分不以 0 代替；建议分与自评分独立 |
| 编辑保护 | 保存失败与多窗口冲突保留编辑；重新生成保留人工正文及自评分 |
| 个人归档 | 当前正文、自评分、理由及来源完整保存，重复确认不重复归档；重新登录可查 |
| 历史保护 | 修改目标或周报后历史归档保持不变；修订形成新版本并保留原版 |
| 异常路径 | 拒绝授权、失效授权、会话失效、AI 超时／限流／非法来源均有明确提示 |
| 人工替代 | AI 未配置或失败时仍可人工保存草稿、自评并归档，不假称采用 AI |
| 运行验证 | 满足第五章首版指标，恢复备份后可查询样例业务记录 |
| 交付记录 | 提供实现范围、配置说明、运行说明及实际验收结果，标记未通过项 |

存在阻断登录、数据丢失、跨用户泄露、错误归档或伪造来源等缺陷时不得判为通过；其余未满足需求项也应修正并复验，未解决问题如实记录。界面可见或演示数据可运行不代替真实飞书、真实 AI 与业务保存验收。

### 8.4 验收记录要求

记录时间、环境、账号脱敏标识、样例材料版本、任务结果、耗时、引用核对结果和问题清单。不得保存完整密钥或令牌。需要用户本人点击授权的步骤标记为人工操作，尚未执行的步骤标记为未验证。
