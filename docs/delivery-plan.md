## 一、交付范围与执行原则

首版交付独立飞书登录页，以及“我的季度目标”“我的周报”“我的绩效汇报”三个一级业务菜单。覆盖 SRS 3.3 的全部 25 项 P0 功能，完成前端、后端、真实联调、测试和部署。

汇报预览、编辑、来源、历史归档和版本记录从对应模块进入，不新增一级菜单。退出登录入口放在登录后的用户菜单中。支持同企业不同员工独立使用，每人仅能访问本人数据。

不包含移动端、主管审批、360 环评、正式绩效评定、组织同步、飞书通知、附件、删除、导入导出及批量处理；按现有需求不生成图形。

执行顺序：设计准备 → Phase 1 前端原型 → Phase 2 后端开发 → Phase 3 真实联调 → Phase 4 测试与上线。各阶段分别验收，前端原型完成不代表业务交付完成。

遵循项目规则：代理执行类型检查、lint及读码核对，不自动启动服务或执行构建。需运行、构建、本人授权及目标环境部署的验证，由用户执行或在明确授权后开展，记录真实结果；未执行时保留未验证状态。不承诺固定开发周数。

后端任务验收要求：

- **B01**：真实飞书授权发起、一次性状态校验、授权码处理、身份和企业核实、稳定身份复用；账号关联成功才建立系统会话。
- **B01**：多浏览器会话独立；退出仅注销当前系统会话，原令牌立即无效，其他会话继续有效；过期必须重新真实授权。
- **B01**：所有新增业务接口均有鉴权，不经过未认证的 `/app/*` 放行；所属人来自服务端认证结果，维护人员无额外业务数据权限。
- **B02**：MySQL持久化O/KR；校验方向、精度、季度截止日期；零负目标合法，缺失进度不写0；保存产生完整历史版本。
- **B02**：重复提交只产生一个有效版本，多窗口版本冲突不覆盖；向周报提供本人指定季度KR，向分析提供指定目标版本。
- **B03**：每人每周唯一且并发安全；自动保存支持版本校验、幂等及完整历史，事项按发生日期归属季度；关联仅允许本人同季度KR。
- **B03**：接入真实AI推荐及共用适配层，读取已保存版本；同版本进行中请求合并，校验推荐KR及引用归属；不修改手动关联和实际进度。
- **B04**：读取本人季度已保存材料，创建输入快照和AI任务；返回分析、建议分、引用、覆盖情况、模型及规则版本；拒绝非法结构和来源。
- **B04**：生成与重新生成保留人工正文、自评分和理由；目标或周报变更可识别旧分析过时；AI失败仍支持人工草稿及归档。
- **B04**：归档事务保存完整独立快照，同次重复确认仅一个版本；历史只读，修订创建新草稿与新归档，保留原版本与来源。

B02/B03 的材料版本机制支持 B04 判断过时状态，不形成反向开发依赖。每项包含对应迁移、接口契约和必要业务验证。
